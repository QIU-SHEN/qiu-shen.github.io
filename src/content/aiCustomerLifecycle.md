# AI 客户生命周期运营引擎

**项目方向：** AI Agent / 客户数据治理 / 生命周期运营

**项目角色：** AI 产品与 Agent 系统设计、全栈开发

**技术栈：** Node.js、Express、MySQL、JavaScript、Qwen-plus、JSON Schema、SSE、PM2、ECS

## 项目简介

面向医美行业非 VIP 老客经营场景，设计并落地一套多 Agent 客户生命周期运营系统。项目将分散在 HIS、CRM/企微、诊疗记录、消费到店、AI 听记及 RFM/NPS 中的历史数据，转化为统一、可信、可追溯的客户全景档案，并进一步生成客户画像、顾问任务、个性化 H5 和沟通话术。

系统强调“证据驱动、人工主导”：AI 负责整理数据、分析客户和生成建议，顾问负责核对、修改和最终执行，避免 AI 自动发送内容或修改业务源库。

## 核心方案

![项目核心业务闭环](/project/ai-customer-lifecycle/01-core-business-loop.png)

- **盘活历史数据：** 通过 5 个档案 Agent 完成跨系统客户身份统一、字段映射、信息归类、特征总结和档案质检，将旧系统数据整理为 230 个标准信息点和 19 个客户特征块。
- **多 Agent 协作：** 设计 17 个专业 Agent，覆盖主控编排、档案治理、画像判断、内容生成、合规审核、反馈学习和运营评估，避免单一大模型承担全部业务判断。
- **形成经营闭环：** 跑通“目标客户筛选 - 全景档案 - 画像分析 - 互动目标 - H5/话术生成 - 顾问审核 - 反馈优化”7 步流程。
- **保证可信合规：** 建立 P1-P4 证据矩阵、低置信度转人工、敏感信息脱敏、禁止自动发送及源库只读等安全机制。

## 个人职责

1. 设计客户全景档案数据架构，将 HIS、CRM、诊疗文档、消费和互动数据统一映射到 230 个标准信息点，并保留数据来源和证据引用。
2. 设计 17 Agent 分层协作流程，为各 Agent 定义 Prompt、输入输出契约、JSON Schema、置信度及人工接管条件。
3. 完成 Node.js/Express 后端、MySQL 数据访问、Agent Runtime、任务队列、事件审计及 SSE 进度推送等核心能力。
4. 搭建全景档案、画像分析、顾问任务与 H5 审核、智能运营 Dashboard 等业务页面。
5. 接入千问模型完成客户特征总结、画像分析和顾问话术生成，并以规则引擎和证据矩阵约束模型输出。
6. 完成本地与 ECS 云端部署，并针对顾问任务进行懒加载和缓存优化。

## 项目成果

- 形成 **376 位客户 × 230 个信息点** 的全景档案矩阵，覆盖约 **8.65 万个客户信息点槽位**。
- 建立 **19 个客户特征块、17 个 Agent、7 步客户经营闭环**。
- 交付全景档案、画像分析、顾问任务与 H5 审核、智能运营 Dashboard 四类核心工作台。
- 建立 30 余个契约校验与构建脚本，覆盖档案、画像、H5、话术、合规和反馈流程。
- 通过任务懒加载与短缓存优化，将重复查询响应由约 **3.5 秒降低至约 12 毫秒**。

## 项目价值

该项目将企业原本分散、难以直接使用的历史客户数据，转化为可以持续更新并直接支持顾问经营的客户数据资产；同时将大模型能力嵌入可审核、可追溯、可人工接管的业务流程，而不是停留在单次内容生成层面。
