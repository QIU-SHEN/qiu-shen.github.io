# 个人主页设计文档

更新时间：2026-07-26

> 本文件从音乐播放器悬浮球迭代开始建立，当前重点记录音乐播放体验的目标设计。后续功能变更继续在此就地更新。

## 音乐播放器悬浮球

### 变更背景

当前全屏播放器把 `<audio>` 放在受 `v-if` 控制的界面容器内。点击关闭按钮后容器被卸载，音频节点随之销毁，因此播放会停止、进度也会丢失。

本次变更要把“关闭播放器”改为“收起播放器”：用户离开全屏界面后，音乐继续播放，并在右下角显示一个可恢复的悬浮球。

### 功能目标

- 点击全屏播放器右上角关闭按钮或按下 `Escape` 后，播放器切换为悬浮球，正在播放的音乐不中断。
- 悬浮球与全屏播放器共用同一个 `<audio>` 实例，不重复加载、不同时播放两个音源。
- 点击悬浮球主体可恢复全屏播放器，播放进度、音量、循环状态保持不变。
- 悬浮球提供播放 / 暂停控制，并提供真正停止播放、移除悬浮球的关闭入口。
- 切换到站内其他路由后，音乐和悬浮球仍然存在。
- 桌面端和移动端均可用，并兼容深色、浅色主题。

### 非目标

- 本次不增加播放列表、上一首 / 下一首、歌词、收藏持久化或媒体快捷键。
- 本次不把播放状态写入 `localStorage`，刷新页面后无需恢复歌曲和进度。
- 本次不增加后端接口、数据库表或静态资源。

### 用户流程

1. 用户进入音乐页面并选择一首歌曲。
2. 全屏播放器打开，用户开始播放并可调节进度、音量和循环状态。
3. 用户点击关闭按钮或按下 `Escape`。
4. 全屏界面收起，右下角出现悬浮球；若歌曲原本正在播放，则继续播放。
5. 用户可以在悬浮球上播放 / 暂停，或点击主体恢复全屏播放器。
6. 用户点击悬浮球的关闭入口时，音频停止，播放状态重置，悬浮球消失。

### 状态设计

播放器使用以下界面状态：

| 状态 | 含义 | 界面表现 |
|---|---|---|
| `idle` | 尚未选择歌曲，或用户已真正关闭播放器 | 不显示全屏播放器和悬浮球 |
| `expanded` | 已选择歌曲且播放器展开 | 显示全屏播放器 |
| `minimized` | 播放器已收起 | 显示右下角悬浮球 |

播放状态 `isPlaying` 与界面状态分离。收起播放器只改变界面状态，不能修改 `isPlaying`、当前进度、音量或循环设置。

### 组件与职责

- `src/App.vue`
  - 全局挂载唯一的播放器实例，使其不受路由页面卸载影响。
- `src/views/music.vue`
  - 保留歌曲列表，只负责把用户选择的歌曲交给播放器状态模块。
- `src/compomnent/musicPlayer.vue`
  - 持有唯一 `<audio>` 节点和全屏播放器界面。
  - 负责播放、暂停、进度、音量、循环、结束事件和错误状态。
  - 收起时隐藏全屏界面，但不卸载音频节点。
- `src/compomnent/miniMusicPlayer.vue`
  - 只负责悬浮球的展示和交互，不创建 `<audio>`。
  - 接收歌曲封面与播放状态，发出恢复、播放 / 暂停、停止事件。
- `src/composables/useMusicPlayer.js`
  - 保存当前歌曲和 `idle / expanded / minimized` 界面状态。
  - 提供选择歌曲、展开、收起、停止等操作，供音乐页面和全局播放器共享。

### 交互与视觉

- 悬浮球使用当前歌曲封面作为主体，播放时显示旋转或呼吸动画，暂停时停止动画。
- 点击悬浮球主体恢复全屏播放器。
- 悬浮球的播放 / 暂停与关闭按钮必须有独立点击区域，避免误触恢复操作。
- 桌面端悬浮球固定在右下角，并位于固定页脚上方。
- 移动端右下角已有任务按钮，音乐悬浮球与其纵向排列并保留间距，同时考虑 `safe-area-inset-bottom`。
- 颜色、边框和阴影优先使用 `src/style.css` 中现有主题变量。
- 所有可点击区域提供中文 `aria-label`，支持键盘聚焦和回车 / 空格操作。

### 音频生命周期约束

- 任意时刻只能存在一个实际工作的 `<audio>` 节点。
- 收起和展开不能重新设置音频 `src`，否则会导致进度重置。
- 只有选择新歌曲或真正停止播放时才允许重置进度。
- `timeupdate`、`ended` 等事件只绑定一次，并在组件卸载时正确移除，避免切歌后重复监听。
- 选择新歌曲时先停止旧音源，再加载新音源；不允许两首歌曲同时播放。

### 异常与边界情况

- 音频尚未完成元数据加载时，时长显示为 `0:00`，控件不能产生无效数值。
- 浏览器拒绝自动播放时保持暂停状态，不伪装成正在播放。
- 音频加载失败时停止加载态并允许用户关闭或重新选择歌曲。
- 歌曲自然播放结束后，非循环模式下回到暂停状态和起始进度；循环模式保持浏览器原生循环行为。
- 用户在悬浮态选择另一首歌曲时，切换到新歌曲并展开全屏播放器。

### 验收标准

- 播放歌曲后点击关闭或按 `Escape`，音乐无可感知中断，进度持续前进。
- 从悬浮球恢复全屏后，进度、音量和循环设置与收起前一致。
- 悬浮球的播放 / 暂停状态与全屏播放器完全同步。
- 在站内切换路由后音乐继续播放，悬浮球仍可操作。
- 真正关闭悬浮球后音频停止、状态重置，页面不再显示播放器。
- 连续切换多首歌曲不会重复播放、重复触发进度事件或产生控制错乱。
- 桌面端、移动端、深色主题和浅色主题下均无遮挡、无重叠和明显误触问题。

### 影响分析

- 改动类型：前端状态调整与局部组件重构。
- 受影响文件：`App.vue`、`music.vue`、`musicPlayer.vue`，并新增悬浮球组件和播放器 composable。
- 数据与接口：无数据库、接口或数据迁移变更。
- 兼容性：保留现有歌曲资源、全屏播放器控件和主题机制。
- 主要风险：音频实例被意外重建、事件监听重复绑定、移动端悬浮按钮重叠；均已纳入验收与回归范围。

## 笔记页面轻量阅读设计

### 设计目标

- 页面从三栏文档后台风格调整为个人编辑式阅读体验，以正文为视觉中心。
- 左侧笔记列表取消面板底色、选中块和装饰性边框，只保留标题、日期与纯文字标签。
- 文章头部去除图标和横向分隔线，保留日期、总字数、阅读时长与标签；粉色只承担链接、标签前缀、代码块细线和当前目录强调。
- Markdown 正文通过留白建立层级，代码块、引用和表格不再使用厚重卡片或完整网格。
- 右侧目录保留层级折叠与正文跳转，普通条目降低对比度，当前条目使用主题色。
- 所有包含子标题的目录分组在笔记加载和切换后默认折叠，需要时通过箭头逐级展开。

### 内容处理

- 页面头部统一展示笔记标题；若 Markdown 第一行是与元数据同名的 `h1` 至 `h3`，渲染时跳过该标题，避免重复。
- 对已跳过首标题后紧随的 `+++` 或 `---` 初始分隔标记同步隐藏。
- 上述处理只作用于渲染内容，不修改 `src/notes/` 中的原始 Markdown。

### 响应式规则

- 常规桌面正文宽度为 `820px`，`1600px` 以上宽屏为 `940px` 并提高正文字号。
- `1100px` 以下隐藏右侧目录；`768px` 以下侧栏位于正文上方并限制为 `36dvh`。
- 深色与浅色主题继续完全使用全局 CSS 变量，页面不引入独立配色状态。

### 验收标准

- 列表页与详情页左侧栏结构、条目数量及高度一致，跳转时不发生布局变化。
- 文章标题不重复，C++、Java、Linux 等旧笔记开头不显示孤立的分隔标记。
- `1366px`、`2048px` 和 `390px` 视口均无横向溢出，正文保持稳定阅读宽度。
- 目录折叠、目录跳转、深浅主题和现有笔记图片继续正常工作。

### 影响分析

- 改动类型：笔记列表与详情页前端视觉重构，附带渲染层内容去重。
- 受影响文件：`src/views/Notes.vue`、`src/views/NoteDetail.vue`、`src/compomnent/tag.vue`。
- 数据与接口：无数据库、接口、路由或 Markdown 源文件变更。

## 公网部署与 AI 代理

### 部署目标

- 网站获得可公开访问的稳定 HTTPS 地址。
- 页面、深层路由、静态图片、字体和 AI 助手在公网环境下完整可用。
- DeepSeek API Key 不进入前端源码、Vite 环境变量或构建产物。

### 架构

- Vite 前端与 `api/chat.js` Vercel Function 部署在同一项目。
- 浏览器只向同域 `/api/chat` 发送经过裁剪的对话历史。
- 云函数在运行时读取 `DEEPSEEK_API_KEY`，添加系统提示词并请求 DeepSeek。
- 前后端分开部署时，可通过 `VITE_CHAT_API_URL` 和 `ALLOWED_ORIGINS` 显式连接。

### 安全与成本约束

- API 仅接受 `POST` 和同源请求，外部来源需要显式加入允许列表。
- 最多保留 10 条历史，单条最多 2000 字符，总上下文最多 8000 字符。
- 单次模型输出限制为 800 tokens，请求超时为 55 秒。
- 服务端错误不向客户端暴露上游响应或密钥。

### 验收标准

- 生产站点根路径及所有现有深层路由直接访问返回 200。
- 前端构建产物中不存在 DeepSeek Key 或 `api.deepseek.com` 直连地址。
- 公网 `/api/chat` 和页面内聊天抽屉均能得到有效回复。
- 桌面端项目图片、自定义字体及 390px 手机笔记页正常加载且无横向溢出。

## GitHub Pages 无 AI 版本

### 目标

- 额外提供一个无需服务端、无需 API Key 的纯静态公开版本。
- 保留 Vercel AI 版本，两种部署从同一套源码构建，互不覆盖。

### 构建差异

- `VITE_ENABLE_AI_ASSISTANT=false`：不挂载 AI 浮动按钮和聊天抽屉，构建产物不包含 `/api/chat` 或 DeepSeek 地址。
- `VITE_USE_HASH_ROUTER=true`：使用 Hash 路由适配 GitHub Pages，避免刷新子路由时返回 404。
- 用户主页仓库 `qiu-shen.github.io` 位于域名根路径，现有 `/dark1.png`、音乐和项目图片无需增加仓库名前缀。

### 发布方式

- 推送 `master` 后，GitHub Actions 使用 Node 22 执行 `npm ci` 与 `npm run build`。
- `actions/upload-pages-artifact` 上传 `dist/`，`actions/deploy-pages` 发布到 GitHub Pages。
- `public/.nojekyll` 防止 Jekyll 处理静态构建产物。

### 验收标准

- 页面中不存在 AI 入口或聊天抽屉，前端 JS 不包含 API 代理路径和 DeepSeek 地址。
- Home、Project、Music、Notes 及笔记详情均能通过 Hash 路由访问。
- Project 三张主题图、音乐封面和移动端布局正常。
